# JavaScript: Scope and Scope Chain

## 1. What is Scope?

**Scope** determines where a variable can be accessed in JavaScript.

In simple terms:

> Scope answers the question: "Where is this variable visible?"

Example:

```js
let name = "Rafi";

function greet() {
  console.log(name);
}

greet();
```

Output:

```txt
Rafi
```

`greet()` can access `name` because `name` exists in an outer scope.

---

# 2. Types of Scope

JavaScript mainly has:

* Global Scope
* Function Scope
* Block Scope

---

## Global Scope

A variable declared outside functions and blocks can be accessed from many places.

```js
let x = 10;

function test() {
  console.log(x);
}

test();
```

Output:

```txt
10
```

Here, `x` belongs to the global scope.

---

## Function Scope

Variables declared with `var` inside a function are function-scoped.

```js
function test() {
  var x = 10;

  console.log(x);
}

test();

console.log(x);
```

Inside the function:

```txt
10
```

Outside the function:

```txt
ReferenceError
```

The `x` variable belongs to the function scope.

---

## Block Scope

`let` and `const` are block-scoped.

A block is created by `{}`.

```js
if (true) {
  let x = 10;
  const y = 20;

  console.log(x); // 10
  console.log(y); // 20
}

console.log(x); // ReferenceError
console.log(y); // ReferenceError
```

The variables only exist inside the block.

---

# 3. Scope Chain

When JavaScript tries to access a variable, it searches through scopes.

The search starts from the current scope and moves outward.

Example:

```js
let x = "global";

function outer() {
  let y = "outer";

  function inner() {
    let z = "inner";

    console.log(z);
    console.log(y);
    console.log(x);
  }

  inner();
}

outer();
```

The lookup for `z`:

```text
inner scope
    ↓
z found
```

The lookup for `y`:

```text
inner scope
    ↓
not found
    ↓
outer scope
    ↓
y found
```

The lookup for `x`:

```text
inner scope
    ↓
not found
    ↓
outer scope
    ↓
not found
    ↓
global scope
    ↓
x found
```

So the scope chain is:

```text
inner
  ↓
outer
  ↓
global
```

If JavaScript cannot find the variable anywhere in the chain:

```js
console.log(unknown);
```

the result is:

```txt
ReferenceError
```

---

# 4. Lexical Scope

JavaScript uses **lexical scoping**.

This means a function's scope is determined by **where the function is defined**, not where the function is called.

Example:

```js
let x = "global";

function outer() {
  let x = "outer";

  return function inner() {
    console.log(x);
  };
}

function test() {
  let x = "test";

  const fn = outer();

  fn();
}

test();
```

Output:

```txt
outer
```

Why?

`inner` was defined inside `outer`.

Therefore its lexical scope is:

```text
inner
  ↓
outer
  ↓
global
```

It does not matter that `fn()` was called from `test()`.

`test` is not part of `inner`'s lexical scope chain.

---

# 5. Lexical Scope vs Calling Location

This is a very important interview concept.

Consider:

```js
let x = "global";

function outer() {
  let x = "outer";

  function inner() {
    console.log(x);
  }

  return inner;
}

const fn = outer();

function test() {
  let x = "test";

  fn();
}

test();
```

Output:

```txt
outer
```

Not:

```txt
test
```

Because `inner` was created inside `outer`.

Its scope chain is based on its definition:

```text
inner
  ↓
outer
  ↓
global
```

Not its call location:

```text
inner
  ↓
test
  ↓
global
```

---

# Key Mental Model

When JavaScript looks for a variable:

```text
Current scope
      ↓
Parent lexical scope
      ↓
Parent lexical scope
      ↓
Global scope
      ↓
ReferenceError
```

The important word is:

> **Lexical**

The scope chain is determined by **where the code is written/defined**, not where the function is called.
