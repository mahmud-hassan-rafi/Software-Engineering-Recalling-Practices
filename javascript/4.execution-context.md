# JavaScript — Execution Context

## 1. What is an Execution Context?

An **Execution Context** is the environment in which JavaScript code is evaluated and executed.

It provides the context in which JavaScript can:

* create and manage variable bindings
* execute statements
* resolve identifiers
* keep track of the currently executing code

The two important types of Execution Context are:

* **Global Execution Context**
* **Function Execution Context**

---

# 2. Global Execution Context

When JavaScript starts executing a program, it creates a **Global Execution Context**.

For example:

```js
var x = 10;

console.log(x);
```

Conceptually:

```text
Global Execution Context
        ↓
JavaScript starts executing the program
        ↓
Global code is evaluated and executed
```

The Global Execution Context exists as the initial execution environment for the program.

---

# 3. Function Execution Context

Whenever a function is **called**, JavaScript creates a new **Function Execution Context** for that function call.

```js
function test() {
  console.log("Hello");
}

test();
```

Conceptually:

```text
Global Execution Context
        ↓
test() is called
        ↓
Function Execution Context for test()
        ↓
test() executes
```

When the function finishes, its execution context is no longer active.

---

# 4. Function Definition vs Function Call

Defining a function does not execute its body.

```js
function test() {
  console.log("Hello");
}
```

At this point, the function body has not executed.

The Function Execution Context is created when:

```js
test();
```

is executed.

Therefore:

```text
Function definition
        ≠
Function execution
```

A function call creates the Function Execution Context.

---

# 5. Creation Phase and Execution Phase

For learning purposes, an Execution Context can be understood in two conceptual phases:

1. **Creation Phase**
2. **Execution Phase**

These phases help explain how JavaScript prepares bindings before executing statements.

---

# 6. Creation Phase

During the Creation Phase, JavaScript prepares the bindings required by the execution context.

Consider:

```js
var x = 10;

function test() {
  var y = 20;
}
```

Conceptually, the Global Execution Context prepares:

```text
Global Environment

x → undefined
test → function
```

The assignment:

```js
x = 10;
```

has not happened yet.

The actual assignment happens during the Execution Phase.

---

## `let` and `const`

`let` and `const` bindings are also created during the setup of the execution context, but they remain **uninitialized** until execution reaches their declaration.

Example:

```js
console.log(x);

let x = 10;
```

The binding for `x` exists, but accessing it before initialization causes a `ReferenceError`.

This period is related to the **Temporal Dead Zone (TDZ)**.

---

# 7. Execution Phase

During the Execution Phase, JavaScript executes statements in their normal order.

Example:

```js
var x = 10;

console.log(x);
```

Conceptually:

```text
Creation Phase:

x → undefined


Execution Phase:

x = 10

x → 10

console.log(x)
```

Output:

```text
10
```

---

# 8. Function Call and Execution Context

Consider:

```js
var x = 10;

function test() {
  var y = 20;

  console.log(x);
  console.log(y);
}

test();
```

The execution can be visualized as:

```text
Global Execution Context
        ↓
x = 10
        ↓
test() called
        ↓
Function Execution Context created
        ↓
y = 20
        ↓
console.log(x)
console.log(y)
        ↓
test() finishes
        ↓
Function Execution Context is no longer active
```

---

# 9. Nested Function Calls

Function calls can create multiple Execution Contexts.

Example:

```js
function first() {
  second();
}

function second() {
  console.log("Hello");
}

first();
```

Conceptually:

```text
Global Execution Context
        ↓
first() called
        ↓
first Function Execution Context
        ↓
second() called
        ↓
second Function Execution Context
        ↓
console.log("Hello")
        ↓
second() finishes
        ↓
first() continues
        ↓
first() finishes
```

This leads directly to the concept of the **Call Stack**, which keeps track of active function calls.

---

# 10. Execution Context vs Scope

Execution Context and Scope are related, but they are not the same concept.

### Scope

Scope answers:

> Where can a variable be accessed?

### Execution Context

Execution Context answers:

> In what execution environment is this code currently being evaluated and executed?

Example:

```js
var x = 10;

function test() {
  var y = 20;

  console.log(x);
  console.log(y);
}

test();
```

When `test()` is called:

```text
Global Execution Context
        ↓
Function Execution Context: test
```

Inside `test()`:

```text
y
```

is available locally, while:

```text
x
```

can be resolved through the function's outer lexical scope.

So:

```js
console.log(x); // 10
console.log(y); // 20
```

---

# 11. Execution Context and Variable Bindings

Consider:

```js
var x = 10;

function test() {
  var x = 20;

  console.log(x);
}

test();
```

Global context:

```text
Global:
x → 10
```

When `test()` is called, a new Function Execution Context is created:

```text
Function: test
x → 20
```

The local `x` is a different binding from the global `x`.

Therefore:

```js
console.log(x);
```

inside `test()` produces:

```text
20
```

The local binding takes precedence during identifier lookup.

---

# 12. Creation Phase Example

Consider:

```js
console.log(a);

var a = 10;

console.log(a);
```

Conceptually:

### Creation Phase

```text
a → undefined
```

### Execution Phase

First:

```js
console.log(a);
```

Output:

```text
undefined
```

Then:

```js
a = 10;
```

Now:

```text
a → 10
```

Finally:

```js
console.log(a);
```

Output:

```text
10
```

Therefore:

```text
undefined
10
```

---

# 13. Function Declaration During Creation

Function declarations are available during the setup of their execution context.

Example:

```js
hello();

function hello() {
  console.log("Hello");
}
```

Output:

```text
Hello
```

Conceptually:

```text
Creation Phase:

hello → function


Execution Phase:

hello()
 ↓
"Hello"
```

This is one of the behaviors commonly described as **hoisting**.

---

# 14. Function Expression and Creation Phase

A function expression behaves differently.

Example:

```js
foo();

var foo = function () {
  console.log("Hello");
};
```

During creation:

```text
foo → undefined
```

When execution reaches:

```js
foo();
```

`foo` is still `undefined`.

Therefore:

```text
TypeError
```

The function value is assigned only when execution reaches:

```js
foo = function () {
  console.log("Hello");
};
```

---

# 15. A Complete Execution Flow

Consider:

```js
var x = 10;

function outer() {
  var y = 20;

  function inner() {
    console.log(y);
  }

  inner();
}

outer();
```

Conceptually:

```text
1. Global Execution Context created
        ↓
2. Global bindings prepared
        ↓
3. Global code executes
        ↓
4. x = 10
        ↓
5. outer() called
        ↓
6. outer Function Execution Context created
        ↓
7. y = 20
        ↓
8. inner() called
        ↓
9. inner Function Execution Context created
        ↓
10. console.log(y)
        ↓
11. inner() finishes
        ↓
12. outer() finishes
```

This example shows how function calls create new Execution Contexts.

---

# 16. Important Mental Model

Think of Execution Context as the **active environment for running a particular piece of JavaScript code**.

```text
Program starts
      ↓
Global Execution Context
      ↓
Function call
      ↓
Function Execution Context
      ↓
Another function call
      ↓
Another Function Execution Context
```

Each active function call has its own execution context.

---

# 17. Key Takeaways

### Execution Context

> The environment in which JavaScript code is evaluated and executed.

### Global Execution Context

> Created when JavaScript starts executing the program.

### Function Execution Context

> Created when a function is called.

### Creation Phase

> Conceptual phase where the execution context's bindings and related execution setup are prepared.

### Execution Phase

> The phase where JavaScript executes statements and performs assignments.

### Function Definition

> Defining a function does not execute its body.

### Function Call

> Calling a function creates a Function Execution Context.

### Important distinction

```text
Function Definition
        ≠
Function Call
        ≠
Function Execution Context
```

---

# Final Mental Model

```text
JavaScript Program
        ↓
Global Execution Context
        ↓
Code starts executing
        ↓
Function call
        ↓
Function Execution Context
        ↓
Function body executes
        ↓
Nested function call
        ↓
Another Function Execution Context
        ↓
Nested function finishes
        ↓
Previous function continues
        ↓
Function finishes
```

The next concept naturally connected to Execution Context is the **Call Stack**, because the Call Stack keeps track of which Execution Context is currently active.
