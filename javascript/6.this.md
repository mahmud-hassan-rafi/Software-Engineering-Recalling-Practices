# JavaScript — `this`

## 1. What is `this`?

`this` is a special value available inside JavaScript functions.

For **regular functions**, the value of `this` is primarily determined by **how the function is called**, not where the function is defined.

```js
const user = {
  name: "Rafi",

  sayName() {
    console.log(this.name);
  }
};

user.sayName();
```

Output:

```text
Rafi
```

Here:

```js
user.sayName();
```

is a method call, so:

```text
this → user
```

Therefore:

```js
this.name
```

is equivalent to:

```js
user.name
```

---

## 2. `this` vs Scope

`this` and scope are different concepts.

### Scope

Scope determines **where variables can be accessed** and where JavaScript looks for a variable.

```js
const name = "Global";

function test() {
  const message = "Hello";

  console.log(message);
}
```

The variable `message` is available because of lexical scope.

### `this`

`this` determines the object/context associated with a **regular function invocation**.

```js
const user = {
  name: "Rafi",

  sayName() {
    console.log(this.name);
  }
};

user.sayName();
```

Here `this` is `user` because of the call:

```js
user.sayName();
```

### Mental Model

```text
Scope
→ Where should I look for a variable?

this
→ What is `this` for this function invocation?
```

---

## 3. Method Call

When a regular function is called as an object's method:

```js
object.method();
```

`this` refers to the object before the dot.

```js
const user = {
  name: "Rafi",

  sayName() {
    console.log(this.name);
  }
};

user.sayName();
```

Output:

```text
Rafi
```

Because:

```text
user.sayName()
     ↑
     this = user
```

---

## 4. Function Reference Does Not Preserve `this`

Consider:

```js
const user = {
  name: "Rafi",

  sayName() {
    console.log(this.name);
  }
};

const fn = user.sayName;
```

This does **not** call the function.

It only stores a reference to the function:

```text
user.sayName
      ↓
   function

fn
 ↓
same function
```

The relationship:

```text
user.sayName()
```

is not permanently attached to the function.

Now:

```js
fn();
```

is a standalone function call.

In strict mode:

```text
this → undefined
```

Therefore:

```js
this.name
```

causes a `TypeError`, because `this` itself is `undefined`.

---

## 5. Same Function, Different `this`

The same function can receive different `this` values depending on how it is called.

```js
const user = {
  name: "Rafi",

  sayName() {
    console.log(this.name);
  }
};

const another = {
  name: "Mahmud",
  say: user.sayName
};

user.sayName();
another.say();
```

Output:

```text
Rafi
Mahmud
```

Why?

The function is the same:

```text
user.sayName
      ↓
   sayName function
```

But the calls are different:

```js
user.sayName();
```

```text
this → user
```

and:

```js
another.say();
```

```text
this → another
```

### Important

The function does not permanently belong to the object where it was originally written.

The **call-site** determines `this` for a regular function.

---

## 6. Standalone Function Call

Consider:

```js
"use strict";

function sayName() {
  console.log(this.name);
}

sayName();
```

This is a standalone function call.

There is no object before the function:

```js
sayName();
```

In strict mode:

```text
this → undefined
```

Therefore:

```js
this.name
```

causes:

```text
TypeError
```

### Non-Strict Mode

For a regular function called standalone in non-strict mode:

```text
this → globalThis
```

The exact observable result depends on the JavaScript environment.

Therefore, when reasoning about `this`, always pay attention to strict mode.

---

## 7. `this` Does Not Come From the Caller

A common misunderstanding is:

> If function `A` calls function `B`, then `B` gets the `this` of `A`.

This is not generally true.

```js
"use strict";

const user = {
  name: "Rafi",

  outer() {
    function inner() {
      console.log(this);
    }

    inner();
  }
};

user.outer();
```

Here:

```js
user.outer();
```

means:

```text
outer's this → user
```

But inside `outer`:

```js
inner();
```

is a standalone call.

Therefore:

```text
inner's this → undefined
```

The caller's `this` is not automatically passed to the called regular function.

---

## 8. `call()`

`call()` allows us to explicitly provide the `this` value.

```js
const user = {
  name: "Rafi"
};

function sayName() {
  console.log(this.name);
}

sayName.call(user);
```

Output:

```text
Rafi
```

Conceptually:

```text
sayName.call(user)
       ↓
this = user
       ↓
execute sayName
```

---

## 9. `apply()`

`apply()` works similarly to `call()`.

```js
sayName.apply(user);
```

Here:

```text
this → user
```

The major difference between `call()` and `apply()` is how arguments are supplied.

```js
function introduce(age, city) {
  console.log(this.name, age, city);
}

const user = {
  name: "Rafi"
};

introduce.call(user, 22, "Dhaka");

introduce.apply(user, [22, "Dhaka"]);
```

Both explicitly set:

```text
this → user
```

---

## 10. `bind()`

`bind()` is different from `call()` and `apply()`.

It does not immediately execute the function.

Instead, it creates a new function with `this` permanently bound to the specified value.

```js
const user = {
  name: "Rafi"
};

function sayName() {
  console.log(this.name);
}

const fn = sayName.bind(user);

fn();
```

Output:

```text
Rafi
```

Conceptually:

```text
sayName
   ↓
bind(user)
   ↓
new bound function
   ↓
fn()
   ↓
this = user
```

Even if the bound function is later stored on another object:

```js
const another = {
  name: "Mahmud",
  fn
};

another.fn();
```

the bound `this` remains:

```text
Rafi
```

because `fn` was already bound to `user`.

---

## 11. `call`, `apply`, and `bind`

| Method    | Executes immediately? | Controls `this`? |
| --------- | --------------------- | ---------------- |
| `call()`  | Yes                   | Yes              |
| `apply()` | Yes                   | Yes              |
| `bind()`  | No                    | Yes              |

Example:

```js
say.call(user);
say.apply(user);

const fn = say.bind(user);
fn();
```

---

## 12. The Most Important Mental Model

For a **regular function**, ask:

### Step 1

How is the function being called?

```js
user.say();
```

Then:

```text
this → user
```

### Step 2

Is it standalone?

```js
say();
```

Then in strict mode:

```text
this → undefined
```

### Step 3

Was `call()` or `apply()` used?

```js
say.call(user);
```

Then:

```text
this → user
```

### Step 4

Was it created using `bind()`?

```js
const fn = say.bind(user);
```

Then:

```text
fn() → this remains user
```

## 13. Function Definition vs Function Invocation

Do not confuse these two:

```js
const user = {
  name: "Rafi",

  sayName() {
    console.log(this.name);
  }
};
```

Defining the function does not permanently set:

```text
this = user
```

Instead, when the function is invoked:

```js
user.sayName();
```

the call-site determines:

```text
this = user
```

The same function can later be called differently:

```js
const fn = user.sayName;

fn();
```

Now it is a standalone call, so its `this` is different.

---

## 14. `this` and Call Stack

`this` and the Call Stack are related to function execution, but they answer different questions.

### Call Stack

The Call Stack answers:

> Which execution context is currently executing?

Example:

```js
function one() {
  two();
}

function two() {
  console.log("two");
}

one();
```

Conceptually:

```text
Call Stack

two()
one()
Global
```

### `this`

`this` answers:

> What `this` value does the current regular function invocation have?

For example:

```js
user.sayName();
```

The function execution is on the Call Stack, while:

```text
this → user
```

is determined by the invocation.

### Mental Model

```text
Call Stack
→ Where is the execution happening?

this
→ What is the `this` value for this function call?
```

## 15. Common Mistakes

### Mistake 1

> `this` is always the object where the function was defined.

False.

```js
const user = {
  name: "Rafi",

  say() {
    console.log(this.name);
  }
};

const fn = user.say;

fn();
```

The function was defined as a property of `user`, but `fn()` is a standalone call.

---

### Mistake 2

> A nested function automatically inherits its parent's `this`.

False for regular functions.

```js
function outer() {
  function inner() {
    console.log(this);
  }

  inner();
}
```

`inner()` is a standalone call.

---

### Mistake 3

> Scope and `this` are the same thing.

They are not.

```text
Scope
→ Variable lookup

this
→ Function invocation context
```

---

## 16. Connection to Arrow Functions

Arrow functions behave differently.

An arrow function does **not create its own `this`**.

Instead, it uses the surrounding lexical `this`.

Example:

```js
const obj = {
  name: "Rafi",

  regular() {
    console.log(this.name);
  }
};
```

Regular functions determine `this` based on invocation.

Arrow functions will be covered separately because their `this` behavior is fundamentally different.

---

# Key Takeaways

1. `this` is not the same as scope.
2. For regular functions, `this` is primarily determined by how the function is called.
3. `object.method()` → `this` is generally `object`.
4. Extracting a method does not preserve its original `this`.
5. `fn()` is a standalone call.
6. In strict mode, a standalone regular function has `this === undefined`.
7. `call()` and `apply()` explicitly set `this` and execute immediately.
8. `bind()` creates a new function with a bound `this`.
9. A called regular function does not automatically inherit the caller's `this`.
10. Arrow functions do not have their own `this`; they use lexical `this`.

## Final Mental Model

```text
Regular Function

How was it called?
       │
       ├── object.method()
       │       ↓
       │    this = object
       │
       ├── function()
       │       ↓
       │    strict → undefined
       │
       ├── function.call(obj)
       │       ↓
       │    this = obj
       │
       ├── function.apply(obj)
       │       ↓
       │    this = obj
       │
       └── function.bind(obj)
               ↓
          bound this = obj
```

> **For regular functions, do not ask "Where was this function defined?" first. Ask "How was this function called?"**
