# JavaScript Prototypes

## 1. What Is a Prototype?

In JavaScript, objects can inherit properties and methods from other objects through a **prototype chain**.

A prototype is simply another object that JavaScript can look at when a property is not found on the current object.

```js
const parent = {
  age: 25
};

const child = Object.create(parent);

child.name = "Rafi";

console.log(child.name); // "Rafi"
console.log(child.age);  // 25
```

`name` belongs directly to `child`.

`age` does not belong to `child`, so JavaScript looks at its prototype (`parent`) and finds it there.

### Mental Model

```text
child
├── name: "Rafi"       ← own property
└── [[Prototype]]
       ↓
     parent
     └── age: 25       ← inherited property
```

A prototype does **not** copy properties into the child.

It creates a relationship that JavaScript can follow during property lookup.

---

# 2. Property Lookup

When accessing:

```js
child.someProperty
```

JavaScript roughly does this:

```text
1. Look on child
2. If not found → follow [[Prototype]]
3. Look on the prototype
4. Continue up the chain
5. If nothing is found → undefined
```

Example:

```js
const grandParent = {
  country: "Bangladesh"
};

const parent = Object.create(grandParent);
parent.city = "Dhaka";

const child = Object.create(parent);
child.name = "Rafi";
```

The chain is:

```text
child
 ↓
parent
 ↓
grandParent
 ↓
null
```

Therefore:

```js
child.name;     // "Rafi"
child.city;     // "Dhaka"
child.country;  // "Bangladesh"
child.age;      // undefined
```

---

# 3. Prototype Chain

The **prototype chain** is the sequence of objects JavaScript follows during property lookup.

A typical chain looks like:

```text
object
  ↓
prototype
  ↓
another prototype
  ↓
Object.prototype
  ↓
null
```

The chain eventually ends at `null`.

If a property cannot be found anywhere in the chain:

```js
object.missingProperty;
```

the result is:

```js
undefined
```

---

# 4. `Object.create()`

`Object.create()` creates a new object whose `[[Prototype]]` is set to the object passed to it.

```js
const user = {
  login() {
    console.log("Logged in");
  }
};

const admin = Object.create(user);
```

Conceptually:

```text
admin
  ↓ [[Prototype]]
user
  └── login()
```

Therefore:

```js
admin.login(); // "Logged in"
```

`admin` does not contain a copied `login` method.

JavaScript finds it through the prototype chain.

---

# 5. `[[Prototype]]`

Every ordinary JavaScript object has an internal relationship called:

```text
[[Prototype]]
```

It points to another object or `null`.

Example:

```js
const parent = {
  age: 25
};

const child = Object.create(parent);
```

Conceptually:

```text
child
 │
 │ [[Prototype]]
 ↓
parent
```

`[[Prototype]]` is an **internal mechanism**, not an ordinary JavaScript property that you normally manipulate directly.

We can inspect it using:

```js
Object.getPrototypeOf(child);
```

---

# 6. `Object.getPrototypeOf()`

`Object.getPrototypeOf()` returns an object's prototype.

```js
const parent = {
  age: 25
};

const child = Object.create(parent);

console.log(Object.getPrototypeOf(child) === parent);
// true
```

The `===` is important.

Objects are compared by **reference identity**, not by their contents.

```js
const a = { city: "Dhaka" };
const b = { city: "Dhaka" };

console.log(a === b); // false
```

They contain the same data, but they are different objects.

However:

```js
const c = a;

console.log(a === c); // true
```

Both variables refer to the exact same object.

---

# 7. `__proto__`

`__proto__` is an accessor that exposes an object's `[[Prototype]]`.

```js
const parent = {
  age: 25
};

const child = Object.create(parent);

console.log(child.__proto__ === parent);
// true
```

### Important distinction

```text
[[Prototype]]
    ↓
Internal object relationship

__proto__
    ↓
Accessor/interface for that relationship

.prototype
    ↓
A property commonly found on constructor functions
```

Do not treat these three as the same thing.

For modern code, prefer:

```js
Object.getPrototypeOf(obj);
```

instead of relying on `__proto__` for normal prototype manipulation.

---

# 8. The `.prototype` Property

This is one of the most confusing parts of JavaScript.

A constructor function can have a property called:

```js
.prototype
```

Example:

```js
function User(name) {
  this.name = name;
}

console.log(User.prototype);
```

`User.prototype` is an object.

We can add shared methods to it:

```js
User.prototype.sayHi = function () {
  console.log("Hi", this.name);
};
```

Now:

```text
User
 │
 │ .prototype
 ↓
User.prototype
 └── sayHi()
```

When an instance is created using `new`:

```js
const rafi = new User("Rafi");
```

the instance's `[[Prototype]]` points to `User.prototype`:

```text
rafi
 │
 │ [[Prototype]]
 ↓
User.prototype
 └── sayHi()
```

Therefore:

```js
Object.getPrototypeOf(rafi) === User.prototype;
// true
```

### Key distinction

```text
User.prototype
    ↓
A property on the User function

rafi.[[Prototype]]
    ↓
An internal link from rafi to User.prototype
```

They are not the same concept, but they are connected.

---

# 9. Constructor Functions

Before `class` syntax became common, constructor functions were widely used to create objects with shared behavior.

```js
function User(name) {
  this.name = name;
}

User.prototype.sayHi = function () {
  console.log("Hi", this.name);
};

const rafi = new User("Rafi");
```

Here:

```text
User
 └── prototype
       ↓
   User.prototype
       └── sayHi()

rafi
 ├── name: "Rafi"
 └── [[Prototype]]
        ↓
    User.prototype
```

`name` is an own property of `rafi`.

`sayHi` is found through the prototype chain.

---

# 10. How `new` Works

Consider:

```js
function User(name) {
  this.name = name;
}

User.prototype.sayHi = function () {
  console.log("Hi", this.name);
};

const rafi = new User("Rafi");
```

The `new` operation can be mentally understood in four major steps.

### Step 1 — Create a new object

Conceptually:

```js
const newObject = {};
```

At this point:

```js
newObject.name; // undefined
```

because nothing has been assigned yet.

### Step 2 — Connect it to `User.prototype`

Conceptually:

```text
newObject
    ↓ [[Prototype]]
User.prototype
```

### Step 3 — Call the constructor with `this`

The constructor runs with:

```js
this === newObject;
```

So:

```js
this.name = name;
```

effectively becomes:

```js
newObject.name = "Rafi";
```

### Step 4 — Return the new object

The resulting object becomes:

```js
rafi
```

Final structure:

```text
rafi
├── name: "Rafi"
└── [[Prototype]]
       ↓
   User.prototype
       └── sayHi()
```

This is the core mental model behind `new`.

---

# 11. Why Prototype Methods Are Shared

Consider:

```js
function User(name) {
  this.name = name;
}

User.prototype.sayHi = function () {
  console.log("Hi", this.name);
};

const rafi = new User("Rafi");
const hasan = new User("Hasan");
```

Both objects can use `sayHi()`:

```js
rafi.sayHi();
hasan.sayHi();
```

But there is not necessarily a separate `sayHi` function stored inside each instance.

Both instances reach the same function through the prototype:

```text
rafi
  ↓
User.prototype
  └── sayHi()

hasan
  ↓
User.prototype
  └── sayHi()
```

Therefore:

```js
rafi.sayHi === hasan.sayHi;
// true
```

This is one of the major practical benefits of prototypes:

> **Shared behavior without creating a separate method function for every instance.**

---

# 12. `Object.prototype`

Most ordinary objects eventually inherit from:

```js
Object.prototype
```

Example:

```js
const user = {
  name: "Rafi"
};
```

Conceptually:

```text
user
 ↓
Object.prototype
 ↓
null
```

That's why methods such as:

```js
user.toString();
```

can work even though `toString` was not explicitly written inside `user`.

The lookup reaches:

```js
Object.prototype.toString
```

Example:

```js
const user = {
  name: "Rafi"
};

console.log(user.toString());
// "[object Object]"
```

`toString()` returns a string representation of the object.

---

# 13. `Object.prototype` Is the End of the Normal Object Chain

`Object.prototype` itself has no object prototype above it:

```js
Object.getPrototypeOf(Object.prototype);
// null
```

So the common chain is:

```text
object
 ↓
Object.prototype
 ↓
null
```

For constructor-based objects, the chain may be longer:

```text
instance
 ↓
User.prototype
 ↓
Object.prototype
 ↓
null
```

---

# 14. `class` and Prototypes

Modern JavaScript provides `class` syntax:

```js
class User {
  constructor(name) {
    this.name = name;
  }

  sayHi() {
    console.log("Hi", this.name);
  }
}
```

Then:

```js
const rafi = new User("Rafi");
```

Although the syntax looks different, JavaScript still uses prototypes.

Conceptually:

```text
rafi
 ↓ [[Prototype]]
User.prototype
 └── sayHi()
 ↓ [[Prototype]]
Object.prototype
 ↓
null
```

The method:

```js
sayHi() {}
```

is placed on:

```js
User.prototype
```

So:

```js
User.prototype.sayHi
```

exists.

And:

```js
Object.getPrototypeOf(rafi) === User.prototype;
// true
```

### Important idea

`class` does not remove the prototype system.

It provides cleaner syntax for working with JavaScript's prototype-based object model.

---

# 15. Prototype Inheritance

Objects can form longer prototype chains.

Example:

```js
const user = {
  login() {
    console.log("User logged in");
  }
};

const admin = Object.create(user);

admin.deleteUser = function () {
  console.log("User deleted");
};
```

The structure is:

```text
admin
 ├── deleteUser()
 └── [[Prototype]]
        ↓
      user
      └── login()
```

Therefore:

```js
admin.deleteUser(); // own method
admin.login();      // inherited method
```

The property lookup automatically moves upward when necessary.

---

# 16. Class Inheritance

The same idea can be expressed using `class`:

```js
class User {
  login() {
    console.log("User logged in");
  }
}

class Admin extends User {
  deleteUser() {
    console.log("User deleted");
  }
}

const admin = new Admin();
```

The important prototype chain is:

```text
admin
 ↓
Admin.prototype
 ↓
User.prototype
 ↓
Object.prototype
 ↓
null
```

So:

```js
admin.deleteUser();
```

is found on:

```text
Admin.prototype
```

while:

```js
admin.login();
```

is found on:

```text
User.prototype
```

This is prototype inheritance.

---

# 17. Property Shadowing

Suppose:

```js
const user = {
  role: "user"
};

const admin = Object.create(user);

admin.role = "admin";
```

Now:

```js
console.log(admin.role);
// "admin"

console.log(user.role);
// "user"
```

Why?

Because JavaScript checks the object's own properties first.

```text
admin
├── role: "admin"       ← found first
└── [[Prototype]]
       ↓
     user
     └── role: "user"
```

The child's own property **shadows** the property with the same name on the prototype.

The prototype property is not deleted or changed.

---

# 18. Removing a Shadowing Property

If we delete the child's property:

```js
delete admin.role;
```

then:

```js
console.log(admin.role);
```

returns:

```text
"user"
```

Why?

Because now the lookup becomes:

```text
admin          ❌ role not found
   ↓
user           ✅ role = "user"
```

This is a useful way to understand how property lookup really works.

---

# 19. Own Properties vs Inherited Properties

Consider:

```js
const user = {
  role: "user"
};

const admin = Object.create(user);

admin.name = "Rafi";
```

Here:

```text
admin
├── name: "Rafi"       ← own
└── [[Prototype]]
       ↓
     user
     └── role: "user"  ← inherited
```

Therefore:

```js
admin.name; // "Rafi"
admin.role; // "user"
```

But `name` and `role` come from different places.

---

# 20. `Object.hasOwn()`

To check whether a property belongs directly to an object:

```js
Object.hasOwn(object, property);
```

Example:

```js
Object.hasOwn(admin, "name");
// true

Object.hasOwn(admin, "role");
// false
```

Even though:

```js
admin.role
```

works, `role` is not an own property of `admin`.

It comes from the prototype.

### Mental Model

```text
Object.hasOwn()
        ↓
"Is this property directly inside THIS object?"
```

It does not search the prototype chain.

---

# 21. `in` Operator

The `in` operator checks the object **and its prototype chain**.

```js
"role" in admin;
```

returns:

```js
true
```

because `role` exists on the prototype.

Compare:

```js
Object.hasOwn(admin, "role");
// false

"role" in admin;
// true
```

### Difference

```text
Object.hasOwn()
    ↓
Own properties only

in
    ↓
Own + inherited properties
```

This distinction is important in interviews and real code.

---

# 22. `instanceof`

`instanceof` checks whether a constructor's `.prototype` appears somewhere in an object's prototype chain.

Example:

```js
class User {}

const rafi = new User();

console.log(rafi instanceof User);
// true
```

Conceptually:

```text
rafi
 ↓
User.prototype  ← found
```

Therefore:

```js
rafi instanceof User;
// true
```

Because `User.prototype` exists in the prototype chain.

It can also reach `Object.prototype`:

```js
rafi instanceof Object;
// true
```

because:

```text
rafi
 ↓
User.prototype
 ↓
Object.prototype  ← found
```

### Mental Model

```text
instanceof
    ↓
"Does Constructor.prototype exist somewhere
 in this object's prototype chain?"
```

---

# 23. Prototype Methods vs Own Methods

Consider:

```js
class User {
  constructor(name) {
    this.name = name;
  }

  sayHi() {
    console.log(this.name);
  }
}
```

Create two objects:

```js
const a = new User("Rafi");
const b = new User("Hasan");
```

Each instance has its own `name`:

```text
a
└── name: "Rafi"

b
└── name: "Hasan"
```

But `sayHi` is shared through the prototype:

```text
a ──→ User.prototype ──→ sayHi
b ──→ User.prototype ──→ sayHi
```

Therefore:

```js
a.sayHi === b.sayHi;
// true
```

This is why prototype methods are memory-efficient compared with creating a new function for every instance.

---

# 24. `Object.setPrototypeOf()`

JavaScript also provides:

```js
Object.setPrototypeOf(object, prototype);
```

Example:

```js
const user = {
  login() {
    console.log("Logged in");
  }
};

const admin = {};

Object.setPrototypeOf(admin, user);

admin.login();
// "Logged in"
```

Now:

```text
admin
 ↓ [[Prototype]]
user
 ↓ [[Prototype]]
Object.prototype
 ↓
null
```

However, changing an object's prototype after creation is generally discouraged in performance-sensitive code.

It is usually better to establish the desired prototype structure when creating the object.

---

# 25. Important Prototype Relationships

There are several different relationships that are easy to confuse.

## `.prototype`

Usually a property of a constructor function:

```js
User.prototype
```

It is an object intended to become the prototype of instances created with:

```js
new User()
```

## `[[Prototype]]`

The internal relationship of an object:

```text
rafi.[[Prototype]] → User.prototype
```

## `__proto__`

An accessor that exposes the object's `[[Prototype]]` relationship:

```js
rafi.__proto__ === User.prototype;
// true
```

## `Object.getPrototypeOf()`

The modern way to inspect that relationship:

```js
Object.getPrototypeOf(rafi) === User.prototype;
// true
```

### Quick Comparison

| Term                      | Meaning                                                 |
| ------------------------- | ------------------------------------------------------- |
| `[[Prototype]]`           | Internal prototype relationship                         |
| `__proto__`               | Accessor for that relationship                          |
| `.prototype`              | Property on a constructor function containing an object |
| `Object.getPrototypeOf()` | Gets an object's prototype                              |
| `Object.setPrototypeOf()` | Changes an object's prototype                           |

# 26. The Complete Mental Model

Consider:

```js
class User {
  constructor(name) {
    this.name = name;
  }

  sayHi() {
    console.log("Hi", this.name);
  }
}

const rafi = new User("Rafi");
```

The important structure is:

```text
                    User
                     │
                     │ .prototype
                     ↓
              User.prototype
                     │
                     │ [[Prototype]]
                     ↓
              Object.prototype
                     │
                     │ [[Prototype]]
                     ↓
                    null
                    

rafi
├── name: "Rafi"
└── [[Prototype]]
       ↓
   User.prototype
       └── sayHi()
```

When we execute:

```js
rafi.name
```

JavaScript finds `name` directly on `rafi`.

When we execute:

```js
rafi.sayHi()
```

JavaScript does not find `sayHi` on `rafi`, so it follows:

```text
rafi
 ↓
User.prototype
```

and finds `sayHi`.

When we execute:

```js
rafi.toString()
```

JavaScript continues:

```text
rafi
 ↓
User.prototype
 ↓
Object.prototype
```

and finds `toString`.

When nothing is found:

```text
rafi
 ↓
User.prototype
 ↓
Object.prototype
 ↓
null
```

the result is:

```js
undefined
```

---

# 27. Prototype: The One Mental Model to Remember

The entire concept can be reduced to this:

> **An object can have another object as its prototype. If a property is not found on the object itself, JavaScript looks up the prototype chain until it finds the property or reaches `null`.**

For constructor/class-based objects:

```text
instance
   ↓
Constructor.prototype
   ↓
Object.prototype
   ↓
null
```

And for inheritance:

```text
child instance
   ↓
Child.prototype
   ↓
Parent.prototype
   ↓
Object.prototype
   ↓
null
```

### Final Rules

```text
1. Own property wins.

2. If not found, follow [[Prototype]].

3. Prototype properties are inherited through lookup,
   not copied into the object.

4. .prototype and [[Prototype]] are different concepts.

5. new connects an instance to Constructor.prototype.

6. class syntax still uses the prototype system.

7. Prototype methods can be shared by many instances.

8. Object.hasOwn() checks own properties only.

9. in checks own + inherited properties.

10. instanceof checks the prototype chain for
    Constructor.prototype.
```

## Final Picture

```text
                 Constructor Function
                         │
                         │ .prototype
                         ↓
                  ┌──────────────┐
                  │   Prototype  │
                  │   sayHi()    │
                  └──────┬───────┘
                         ↑
                         │ [[Prototype]]
                         │
                    ┌────┴────┐
                    │ instance │
                    │ name     │
                    │ "Rafi"   │
                    └──────────┘
```

**Prototype = object-to-object inheritance through property lookup.**

Once this model is clear, `new`, `class`, `extends`, `instanceof`, and shared methods all become much easier to understand.
