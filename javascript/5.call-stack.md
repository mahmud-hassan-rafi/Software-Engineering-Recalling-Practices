# JavaScript — Call Stack

## 1. What is the Call Stack?

The **Call Stack** is a stack used by JavaScript to keep track of the currently active execution contexts.

It follows the **LIFO** principle:

> **Last In → First Out**

When a function is called, its execution is added to the Call Stack.

When the function finishes, its execution is removed from the Call Stack.

Conceptually:

```text
Function Call
     ↓
Execution Context / Stack Frame is pushed
     ↓
Function executes
     ↓
Function returns
     ↓
Frame is popped
```

---

## 2. Simple Example

```js
function first() {
  console.log("First");
}

function second() {
  console.log("Second");
}

first();
second();
```

When `first()` is called:

```text
┌─────────────┐
│ first()     │
├─────────────┤
│ Global      │
└─────────────┘
```

When `first()` finishes:

```text
┌─────────────┐
│ Global      │
└─────────────┘
```

Then `second()` is called:

```text
┌─────────────┐
│ second()    │
├─────────────┤
│ Global      │
└─────────────┘
```

When `second()` finishes:

```text
┌─────────────┐
│ Global      │
└─────────────┘
```

---

## 3. Call Stack and Execution Context

A function call creates a **Function Execution Context**.

That execution context becomes active and is represented conceptually as a **stack frame** in the Call Stack.

Therefore:

```text
Function Call
     ↓
Function Execution Context
     ↓
Call Stack Frame
```

A useful mental model is:

> **Execution Context = what execution is happening.**

> **Call Stack = which executions are currently active and which one will resume next.**

---

## 4. Variables Are Not Separate Stack Items

Consider:

```js
function test() {
  var x = 10;
  let y = 20;

  console.log(x + y);
}

test();
```

The Call Stack does **not** look like this:

```text
❌
x
y
test()
Global
```

Instead, conceptually:

```text
┌──────────────────┐
│ test() frame     │
│                  │
│ x → 10           │
│ y → 20           │
├──────────────────┤
│ Global frame     │
└──────────────────┘
```

`x` and `y` are **bindings associated with the execution environment of `test()`**.

They are not separate Call Stack entries.

---

## 5. Creation Phase vs Call Stack

When a function is called:

```js
function test() {
  var x = 10;
  let y = 20;
}

test();
```

Conceptually, the following happens:

### Step 1 — Function Call

```text
test()
```

A Function Execution Context is created and becomes active.

### Step 2 — Creation Phase

Bindings are prepared.

Conceptually:

```text
x → undefined
y → uninitialized (TDZ)
```

### Step 3 — Execution Phase

The statements execute:

```text
x → 10
y → 20
```

At the same time, the Call Stack looks conceptually like:

```text
┌──────────────┐
│ test()       │
├──────────────┤
│ Global       │
└──────────────┘
```

Important distinction:

> **Creation Phase belongs to the Execution Context.**

> **Call Stack tracks the active execution contexts.**

They are related, but they are not the same concept.

---

## 6. Nested Function Calls

Consider:

```js
function a() {
  console.log("A");
  b();
  console.log("A end");
}

function b() {
  console.log("B");
  c();
  console.log("B end");
}

function c() {
  console.log("C");
}

a();
```

When `a()` starts:

```text
┌─────────────┐
│ a()         │
├─────────────┤
│ Global      │
└─────────────┘
```

When `a()` calls `b()`:

```text
┌─────────────┐
│ b()         │
├─────────────┤
│ a()         │
├─────────────┤
│ Global      │
└─────────────┘
```

When `b()` calls `c()`:

```text
┌─────────────┐
│ c()         │
├─────────────┤
│ b()         │
├─────────────┤
│ a()         │
├─────────────┤
│ Global      │
└─────────────┘
```

`c()` finishes first:

```text
┌─────────────┐
│ b()         │
├─────────────┤
│ a()         │
├─────────────┤
│ Global      │
└─────────────┘
```

Then `b()` finishes:

```text
┌─────────────┐
│ a()         │
├─────────────┤
│ Global      │
└─────────────┘
```

Finally `a()` finishes:

```text
┌─────────────┐
│ Global      │
└─────────────┘
```

Therefore:

```text
A
B
C
B end
A end
```

---

## 7. The Most Important Rule

When a function calls another function:

```js
function a() {
  b();
  console.log("A");
}
```

`console.log("A")` does **not** execute immediately.

JavaScript must first complete:

```js
b();
```

Only after `b()` returns can execution continue:

```js
console.log("A");
```

Mental model:

```text
a()
 ↓
b()
 ↓
b() finishes
 ↓
return to a()
 ↓
continue after b()
```

---

## 8. LIFO — Last In, First Out

The Call Stack follows LIFO.

Example:

```text
a()
 ↓
b()
 ↓
c()
```

Stack:

```text
┌─────────────┐
│ c()         │ ← last in
├─────────────┤
│ b()         │
├─────────────┤
│ a()         │
├─────────────┤
│ Global      │
└─────────────┘
```

Therefore:

```text
c() → finishes first
b() → finishes second
a() → finishes third
```

The last function pushed is the first one popped.

---

## 9. Recursion and Stack Overflow

Consider:

```js
function first() {
  second();
}

function second() {
  first();
  console.log("Hello");
}

second();
```

The stack keeps growing:

```text
second()
first()
second()
first()
second()
first()
...
```

Neither function gets a chance to return.

Therefore, the Call Stack eventually becomes too deep:

```text
RangeError: Maximum call stack size exceeded
```

This is called a **stack overflow**.

---

## 10. Why `console.log()` May Never Execute

In:

```js
function second() {
  first();
  console.log("Hello");
}
```

`console.log("Hello")` is after the call to `first()`.

If `first()` never returns:

```text
first()
  ↓
second()
  ↓
first()
  ↓
second()
  ↓
...
```

execution never reaches:

```js
console.log("Hello");
```

The key rule is:

> A function must return before the caller can continue to the next statement after that function call.

## 11. Call Stack vs Scope Chain

These are different concepts.

### Call Stack

Answers:

> **Which executions are currently active?**

Example:

```text
Global
 ↓
a()
 ↓
b()
```

### Scope Chain

Answers:

> **Where should JavaScript look for a variable?**

For a lexically nested function:

```text
inner
 ↓
outer
 ↓
Global
```

These two structures can look similar, but they represent different things.

### Important

Being lower in the Call Stack does **not** automatically make a function a lexical parent.

For example:

```js
function a() {
  var x = 10;
  b();
}

function b() {
  var y = 20;
  console.log(y);
}

a();
```

When `b()` runs:

```text
Call Stack:

b()
a()
Global
```

But `b` was defined globally, not inside `a`.

Therefore its lexical lookup is conceptually:

```text
b
 ↓
Global
```

Not:

```text
b
 ↓
a
 ↓
Global
```

This is an important distinction:

> **Call Stack relationship ≠ Lexical Scope relationship**

---

## 12. Global Execution Context

The Global Execution Context is conceptually the bottom/root execution context while the JavaScript program is running.

For example:

```js
var x = 10;

function test() {
  console.log(x);
}

test();
```

Conceptually:

```text
┌─────────────┐
│ test()      │
├─────────────┤
│ Global      │
└─────────────┘
```

Global bindings belong to the **Global Environment**.

They are not separate Call Stack items:

```text
❌
x
test
Global
```

Instead:

```text
┌─────────────────────┐
│ Global frame        │
│                     │
│ x → 10              │
│ test → function     │
└─────────────────────┘
```

---

## 13. Call Stack Does Not Equal Memory

Do not use this oversimplified rule:

> "Variables are in the stack and objects are in the heap."

Real JavaScript engine implementations are more complex.

For our mental model:

```text
Call Stack
    ↓
Tracks active execution

Execution Environment
    ↓
Contains/accesses bindings and execution-related state

Scope Chain
    ↓
Determines lexical variable lookup

Heap
    ↓
A general memory area used by the engine for dynamically allocated data
```

These concepts are related but not interchangeable.

---

## 14. Function Completion and Garbage Collection

When a function finishes, its active Call Stack frame is removed.

For example:

```text
Before return:

b()
a()
Global
```

After `b()` finishes:

```text
a()
Global
```

However:

> **A frame leaving the Call Stack does not automatically mean that every binding associated with it is immediately destroyed.**

Consider:

```js
function create() {
  let x = 10;

  return function () {
    console.log(x);
  };
}

const fn = create();
```

`create()` finishes, so its active frame is removed.

But `x` can remain reachable through the returned function because of the closure.

Therefore:

```text
Call Stack:
Global
```

while conceptually the returned function still has access to:

```text
x → 10
```

Garbage collection is about reclaiming memory that is no longer reachable, not simply about popping a Call Stack frame.

---

# 15. Core Mental Model

Keep these four concepts separate:

```text
┌──────────────────────────────────────┐
│            CALL STACK                │
│                                      │
│ Tracks active executions             │
└──────────────────────────────────────┘

                 ↓

┌──────────────────────────────────────┐
│        EXECUTION CONTEXT             │
│                                      │
│ Environment for a particular         │
│ execution                            │
└──────────────────────────────────────┘

                 ↓

┌──────────────────────────────────────┐
│       BINDINGS / ENVIRONMENT         │
│                                      │
│ Variables/functions are associated   │
│ with the relevant environment        │
└──────────────────────────────────────┘

                 ↓

┌──────────────────────────────────────┐
│          SCOPE CHAIN                 │
│                                      │
│ Determines lexical variable lookup   │
└──────────────────────────────────────┘
```

### One-line mental model

> **Call Stack tells us what is executing; Execution Context provides the execution environment; bindings belong to that environment; Scope Chain determines where lexical variables are searched.**

---

# Key Takeaways

* Call Stack follows **LIFO**.
* A function call creates a Function Execution Context.
* The active execution is represented conceptually by a stack frame.
* Variables are **not separate Call Stack entries**.
* Bindings belong to the relevant execution environment.
* Creation Phase prepares bindings; it is not the same thing as the Call Stack.
* Global Execution Context is conceptually at the bottom while the program is running.
* Nested calls create multiple stack frames.
* A caller cannot continue until the called function returns.
* Infinite recursion can cause **stack overflow**.
* Call Stack and Scope Chain are different concepts.
* Call Stack position does **not** determine lexical scope.
* Leaving the Call Stack does not automatically mean all associated memory is immediately garbage-collected.
